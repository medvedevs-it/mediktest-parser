# Исправление повторов ситуационных задач

Изменяется программа, а не содержимое рабочей базы. Задачи со старого сайта
могут приходить повторно: такие выдачи учитываются как повторы, а не как
новые задачи в банке или новые уникальные задачи для достижения цели запуска.

## Правила

- Для готовой задачи сравниваются всё содержимое и изображения, правильность
  ответов и порядок вопросов. Порядок вариантов ответа не влияет на совпадение.
- Игнорируются только явно перечисленные служебные поля верхнего уровня.
- Разные вопросы, ключи ответов или изображения сохраняются раздельно.
- Одинаковое условие не является достаточным основанием для объединения.
- Сопоставление изолировано по специальности и режиму источника.
- Проверка и запись готовой задачи выполняются в одной транзакции.
- Счётчик запуска использует идентификатор сохранённой записи, а не номер
  внешней попытки. Это соответствует восстановлению, прогрессу и выгрузкам.
- Повтор не завершает сбор сам по себе: поиск продолжается до уникальной цели
  либо действующего защитного лимита/команды пользователя.

## Проверки

`python -m unittest discover -s tests`: 156 проверок в релизной ветке,
включая запуск в linux/amd64-контейнере без сети.

Новые сквозные проверки воспроизводили прежнюю ошибку: цель «2 задачи»
достигалась после двух выдач одной и той же задачи. После исправления:

1. Три выдачи одной задачи, затем новая задача: выполнены все четыре попытки;
   две уникальные задачи в прогрессе и выгрузке. Обе специальности.
2. Перезапуск после первой выдачи: новые номера попыток не увеличивают цель.
3. Уже существующая задача из другого запуска: запись и ID переиспользуются;
   три повторных выдачи не выдаются за три уникальные задачи.

Для дополнительной проверки на копии клиентской базы служит
`scripts/verify-case-replay.py`: открывает источник readonly, использует
временную пустую базу, вызывает обычный RunManager с подставленным источником
сохранённых задач, сверяет счётчики/содержимое выгрузок и SQLite integrity.
Это офлайн-проверка, не сбор с сайта. База и данные клиента в Git не включены.

На копии базы от 02.11.2026 проверены все 984 исходные записи Лечебного дела:
956 различных готовых задач, 28 повторов; прогресс, выгрузка запуска и банка
согласованы (956). Пройдено 984 попытки, штатная остановка по установленному
числу попыток; SQLite integrity — ok. Время офлайн-воспроизведения: 251,63 с.

## Установка

Ветка основана на `codex/reh2-release` (8959d38), содержит предыдущее
исправление сравнения задач (4170bfb) и исправление счётчика запуска.
Перед выпуском/установкой сверить фактически работающий тег и наличие
дополнительных изменений на сервере Сергея. Не заменять их старой версией.
Установка — между запусками, после согласованного резервного копирования.

Исторические дубли не удаляются и клиентские ID не перенумеровываются.
Не обещать, что ранее накопленный банк автоматически уменьшится.
Случайная выдача сайта не гарантирует получение полного банка задач.
