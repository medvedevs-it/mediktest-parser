# MedikTest — контракт данных и экспорта

## Внутренний материал

Каждый материал имеет:

- `kind`: `test` или `case`;
- `source_id`: исходный идентификатор, если доступен;
- `content_hash`: отпечаток нормализованного содержания;
- `version`;
- `first_seen_at`, `last_seen_at`;
- `status`: `ready`, `missing_key`, `incomplete`, `invalid`;
- исходный `raw_payload`;
- нормализованный `payload`.

## Тестовый вопрос

- текст вопроса;
- номер в попытке и общее число вопросов, если доступны;
- варианты в исходном порядке;
- для каждого варианта: текст и `is_correct`;
- статус раскрытия ключа;
- признак `single_answer = true`.

Готовым считается вопрос, у которого подтверждён правильный вариант и для остальных вариантов установлено `false`.

## Ситуационная задача

- заголовок;
- полное условие;
- упорядоченные разделы условия;
- исходный ID варианта;
- упорядоченный список всех вопросов;
- для каждого вопроса — варианты, кратность ответа и статус ключа;
- ожидаемое и фактически прочитанное количество вопросов.
- изображения разделов: исходное имя файла, контрольная сумма, тип и статус
  успешного сохранения.

Кейс считается готовым только при полном условии, полном наборе вопросов и раскрытых ключах для каждого вопроса.

## Клиентские ID

Клиентские ID выделяются из отдельной последовательности и сохраняются в SQLite.

- уже экспортированный материал при обновлении сохраняет ID;
- новая версия материала не получает новый ID;
- новый материал получает следующий свободный ID;
- удаление материала не освобождает ID;
- варианты ответа получают стабильные ID, связанные с ID вопроса.

## Excel

Источник истины — последние присланные клиентом шаблоны. Экспорт формируется одной объединённой книгой.

- тесты: один лист `Tests` с колонками `№`, `Вопрос`, `Правильный ответ`,
  `Ответ 2`, `Ответ 3`, `Ответ 4`;
- ситуационные задачи: листы `exercise_rows`, `questions`, `answers`;
- названия, порядок колонок и типы значений не меняются;
- служебная статистика не добавляется в эти листы.

Если нужен отчёт запуска, он создаётся отдельным файлом либо хранится в JSON.

Изображения не встраиваются в `.xlsx`. Их имена записываются в соответствующий
`text_after` (или условие, если изображение относится к условию), а сами файлы
выдаются отдельным ZIP с путями `images/<исходное_имя_файла>`. При совпадении
имени у разных файлов экспорт прерывается, чтобы не сформировать неверную связь.

В режиме `catalog` книга содержит весь накопленный банк. В режиме `new` книга содержит только уникальные готовые материалы текущего запуска, включая уже известные общему банку повторы.

## JSON

JSON содержит:

- обезличенные параметры и результат запуска;
- статистику;
- полный снимок накопленного каталога тестов и кейсов на момент завершения запуска;
- `run_delta` со списком новых и изменённых материалов конкретного запуска;
- ошибки и пропуски без логинов, паролей и внутренних трассировок.
- `image_assets` с клиентскими именами, контрольными суммами и привязкой к
  исходным ID кейсов; внутренние имена хранения не экспортируются.

Excel и JSON должны содержать одинаковое число готовых материалов.
